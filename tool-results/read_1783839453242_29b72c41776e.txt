     5→# Create a chat completion
     6→
     7→> Use CometAPI POST /v1/chat/completions to send multi-message conversations to chat models with streaming, temperature, and max_tokens controls.
     8→
     9→CometAPI routes Chat Completions to multiple providers — including OpenAI, Claude, and Gemini — through a single OpenAI-compatible interface. Switch between models by changing the `model` parameter; most OpenAI-compatible SDKs work by setting `base_url` to `https://api.cometapi.com/v1`.
    10→
    11→<Warning>
    12→  Request parameters and response fields can vary significantly between model providers. Check the official documentation for the provider behind the model you use whenever you need the complete parameter list or provider-specific behavior. For example, `reasoning_effort` only applies to reasoning models (o-series, GPT-5.1+), and some models do not support `logprobs` or `n` > 1.
    13→</Warning>
    14→
    15→<Note>
    16→  For OpenAI Pro models, o-series reasoning models, and Codex models, use the [Responses](/api/text/responses) endpoint instead. These model families have more complete support on the Responses API.
    17→</Note>
    18→
    19→***
    20→
    21→## Message roles
    22→
    23→| Role        | Description                                                                                                       |
    24→| ----------- | ----------------------------------------------------------------------------------------------------------------- |
    25→| `system`    | Sets the assistant's behavior and personality. Placed at the start of the conversation.                           |
    26→| `developer` | Replaces `system` for newer models (o1+). Provides instructions the model should follow regardless of user input. |
    27→| `user`      | Messages from the end user.                                                                                       |
    28→| `assistant` | Previous model responses, used to maintain conversation history.                                                  |
    29→| `tool`      | Results from tool/function calls. Must include `tool_call_id` matching the original tool call.                    |
    30→
    31→<Tip>
    32→  For newer models (GPT-4.1, GPT-5 series, o-series), prefer `developer` over `system` for instruction messages. Both work, but `developer` provides stronger instruction-following behavior.
    33→</Tip>
    34→
    35→***
    36→
    37→## Send multimodal input
    38→
    39→Many models support images and audio alongside text. To send multimodal messages, use the array format for `content`:
    40→
    41→```json theme={null}
    42→{
    43→  "role": "user",
    44→  "content": [
    45→    {"type": "text", "text": "Describe this image"},
    46→    {
    47→      "type": "image_url",
    48→      "image_url": {
    49→        "url": "https://example.com/image.png",
    50→        "detail": "high"
    51→      }
    52→    }
    53→  ]
    54→}
    55→```
    56→
    57→The `detail` parameter controls image analysis depth:
    58→
    59→* `low` — faster, uses fewer tokens (fixed cost)
    60→* `high` — detailed analysis, more tokens consumed
    61→* `auto` — the model decides (default)
    62→
    63→***
    64→
    65→## Stream responses
    66→
    67→To receive incremental output, set `stream` to `true`. The response is delivered as **Server-Sent Events (SSE)**, where each event contains a `chat.completion.chunk` object:
    68→
    69→```
    70→data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"role":"assistant"},"finish_reason":null}]}
    71→
    72→data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}]}
    73→
    74→data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"!"},"finish_reason":null}]}
    75→
    76→data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}
    77→
    78→data: [DONE]
    79→```
    80→
    81→<Tip>
    82→  To include token usage statistics in streaming responses, set `stream_options.include_usage` to `true`. The usage data appears in the final chunk before `[DONE]`.
    83→</Tip>
    84→

    87→## Request structured output
    88→
    89→To force the model to return valid JSON matching a specific schema, use `response_format`:
    90→
    91→<CodeGroup>
    92→  ```json JSON Schema Mode theme={null}
    93→  {
    94→    "response_format": {
    95→      "type": "json_schema",
    96→      "json_schema": {
    97→        "name": "result",
    98→        "strict": true,
    99→        "schema": {
   100→          "type": "object",
   101→          "properties": {
   102→            "answer": {"type": "string"},
   103→            "confidence": {"type": "number"}
   104→          },
   105→          "required": ["answer", "confidence"],
   106→          "additionalProperties": false
   107→        }
   108→      }
   109→    }
   110→  }
   111→  ```
   112→
   113→  ```json JSON Object Mode theme={null}
   114→  {
   115→    "response_format": {"type": "json_object"}
   116→  }
   117→  ```
   118→</CodeGroup>
   119→
   120→<Note>
   121→  JSON Schema mode (`json_schema`) guarantees the output matches your schema exactly. JSON Object mode (`json_object`) only guarantees valid JSON — the structure is not enforced.
   122→</Note>

   126→## Call tools and functions
   127→
   128→To enable the model to call external functions, provide tool definitions:
   129→
   130→```json theme={null}
   131→{
   132→  "tools": [
   133→    {
   134→      "type": "function",
   135→      "function": {
   136→        "name": "get_weather",
   137→        "description": "Get current weather for a city",
   138→        "parameters": {
   139→          "type": "object",
   140→          "properties": {
   141→            "location": {"type": "string", "description": "City name"}
   142→          },
   143→          "required": ["location"]
   144→        }
   145→      }
   146→    }
   147→  ],
   148→  "tool_choice": "auto"
   149→}
   150→```
   151→
   152→When the model decides to call a tool, the response will have `finish_reason: "tool_calls"` and the `message.tool_calls` array will contain the function name and arguments. You then execute the function and send the result back as a `tool` message with the matching `tool_call_id`.

   156→## Cross-provider notes
   157→
   158→<AccordionGroup>
   159→  <Accordion title="Parameter support across providers">
   160→    | Parameter          | OpenAI GPT         | Claude (via compat) | Gemini (via compat)                  |
   161→    | ------------------ | ------------------ | ------------------- | ------------------------------------ |
   162→    | `temperature`      | 0–2                | 0–1                 | 0–2                                  |
   163→    | `top_p`            | 0–1                | 0–1                 | 0–1                                  |
   164→    | `n`                | 1–128              | 1 only              | 1–8                                  |
   165→    | `stop`             | Up to 4            | Up to 4             | Up to 5                              |
   166→    | `tools`            | ✅                  | ✅                   | ✅                                    |
   167→    | `response_format`  | ✅                  | ✅ (json\_schema)    | ✅                                    |
   168→    | `logprobs`         | ✅                  | ❌                   | ❌                                    |
   169→    | `reasoning_effort` | o-series, GPT-5.1+ | ❌                   | ❌ (use `thinking` for Gemini native) |
   170→  </Accordion>
   171→
   172→  <Accordion title="max_tokens vs max_completion_tokens">
   173→    * **`max_tokens`** — The legacy parameter. Works with most models but is deprecated for newer OpenAI models.
   174→    * **`max_completion_tokens`** — The recommended parameter for GPT-4.1, GPT-5 series, and o-series models. Required for reasoning models as it includes both output tokens and reasoning tokens.
   175→
   176→    CometAPI automatically handles the mapping when routing to different providers.
   177→  </Accordion>
   178→
   179→  <Accordion title="system vs developer role">
   180→    * **`system`** — The traditional instruction role. Works with all models.
   181→    * **`developer`** — Introduced with o1 models. Provides stronger instruction-following for newer models. Falls back to `system` behavior on older models.
   182→
   183→    Use `developer` for new projects targeting GPT-4.1+ or o-series models.
   184→  </Accordion>
   185→</AccordionGroup>

   189→## FAQ
   190→
   191→### How to handle rate limits?
   192→
   193→When encountering `429 Too Many Requests`, implement exponential backoff:
   194→
   195→```python theme={null}
   196→import os
   197→import time
   198→import random
   199→from openai import OpenAI, RateLimitError
   200→
   201→client = OpenAI(
   202→    base_url="https://api.cometapi.com/v1",
   203→    api_key=os.environ["COMETAPI_KEY"],
   204→)
   205→
   206→def chat_with_retry(messages, max_retries=3):
   207→    for i in range(max_retries):
   208→        try:
   209→            return client.chat.completions.create(
   210→                model="gpt-5.4",
   211→                messages=messages,
   212→            )
   213→        except RateLimitError:
   214→            if i < max_retries - 1:
   215→                wait_time = (2 ** i) + random.random()
   216→                time.sleep(wait_time)
   217→            else:
   218→                raise
   219→```
   220→
   221→### How to maintain conversation context?
   222→
   223→Include the full conversation history in the `messages` array:
   224→
   225→```python theme={null}
   226→messages = [
   227→    {"role": "developer", "content": "You are a helpful assistant."},
   228→    {"role": "user", "content": "What is Python?"},
   229→    {"role": "assistant", "content": "Python is a high-level programming language..."},
   230→    {"role": "user", "content": "What are its main advantages?"},
   231→]
   232→```
   233→
   234→### What does `finish_reason` mean?
   235→
   236→| Value            | Meaning                                                |
   237→| ---------------- | ------------------------------------------------------ |
   238→| `stop`           | Natural completion or hit a stop sequence.             |
   239→| `length`         | Reached `max_tokens` or `max_completion_tokens` limit. |
   240→| `tool_calls`     | The model invoked one or more tool/function calls.     |
   241→| `content_filter` | Output was filtered due to content policy.             |
   242→
   243→### How to control costs?
   244→
   245→1. Use `max_completion_tokens` to cap output length.
   246→2. Choose cost-effective models (e.g., `gpt-5.4-mini` or `gpt-5.4-nano` for simpler tasks).
   247→3. Keep prompts concise — avoid redundant context.
   248→4. Monitor token usage in the `usage` response field.
